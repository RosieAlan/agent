## 协议示例

下面沿用合成广告报表作协议示意，当前尚无对应新Python HTTP返回：

```json
{
  "message": "已查询到广告报表，以下数据来自合成样例。",
  "components": [
    {
      "type": "card",
      "title": "广告活动 AD-DEMO-001",
      "fields": [
        {"label": "花费", "value": "100 CNY"},
        {"label": "归因销售额", "value": "250 CNY"},
        {"label": "ROAS", "value": "2.5"}
      ]
    },
    {
      "type": "selection",
      "title": "接下来做什么？",
      "options": [
        {"id": "generate_report", "label": "生成分析报告"},
        {"id": "explain_metrics", "label": "查看指标说明"}
      ],
      "allowMultiple": false
    }
  ]
}
```

type是前后端约定的种类名称；card对应已有详情组件，fields提供展示字段；selection对应已有选择组件，options是选项，id提供后端判断依据，label供用户阅读。allowMultiple=false表示单选。后端在本项目确定金额/ROAS等事实字段，模型可生成说明或建议，随后Schema和业务校验共同检查；页面只渲染已支持组件。

用户选择“生成分析报告”回传：

```json
{
  "componentType": "selection",
  "payload": {
    "type": "select",
    "selectedId": "generate_report"
  }
}
```

这份数据叫UIAction；后端需要根据选项id和已保存阶段处理，重新核对用户、会话和允许选项。客户端payload和context可被修改，正式权限/状态由服务端可信记录提供。为避免混用原课与新扩展，当前示例保持原UIAction字段，动作编号/版本/幂等在状态实作时明确追加。

## 八类组件完整范围

text显示文字；card显示一个对象详情；table显示多行；selection选择选项；form收集输入；confirmation确认已展示方案；steps显示执行进度；action_buttons提供快捷操作。前端ComponentRenderer按type映射已有组件，AIChatContainer管理对话、请求和动作回传。后端通过Pydantic对应原Zod判别联合，模型输出/业务组装产生组件，结构化校验后再返回。

## 动作、审批和状态

完整业务练习沿用只读查询与生成报告：选择分析范围→填写指标/时间→确认生成条件→生成结果，状态推进由后端按既定规则处理。前端确认按钮提交用户选择；后端保存确认结果并校验有效性。后续涉及预算写入时还需主管身份与对象权限、方案版本、幂等及外部API授权，现阶段预算写入和通知尚未接入。

## 必背与检查题答案

Q：什么是UI协议？A：前后端约定的一份JSON结构，描述页面展示哪些组件、组件显示什么、用户操作返回哪些字段。message展示说明，components驱动已有组件，UIAction回传操作。

Q：与D03结构化输出的联系？A：D03把模型结果整理为action/constraints等业务字段；D08把业务结果整理为card/selection/form等交互字段。两者均先约定结构再校验，事实与权限另按可信业务数据验证。

Q：按钮文案改为“立即生成”，为什么后端仍能判断动作？A：后端读取稳定的selectedId=generate_report；用户看到的label用于显示。

Q：模型生成confirmation、浏览器显示按钮，能否证明主管已批准？A：已批准需要后端取得经过认证的操作人，检查其权限、确认对象与方案版本，并成功保存批准记录。UI组件表示当前交互内容；审批记录表示已经发生的业务确认。

Q：本轮是否已经修改Python接口？A：本轮讲协议与调用关系，尚无业务源码/数据库变更；下一块在app/schemas与后端服务中实现校验和可信结果组装。
