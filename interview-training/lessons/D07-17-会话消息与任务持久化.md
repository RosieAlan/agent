## 本块目标与调用顺序

必备：按用户校验会话，持久化用户/助手消息，历史实际传入模型，模型等待期间释放连接。熟练：短事务、同会话并发409、任务状态与错误处理。了解：JSONB与时间/顺序列。进程强杀恢复、完整JWT、Token预算、幂等请求重放和线上日志平台仍按后续单元接入。

浏览器POST /conversations创建会话；POST /conversations/{id}/chat → api/conversations.chat → services/conversation_service.chat_in_conversation → repositories/conversation_repository.start_turn → services/llm_service.run_ad_tool(input, history) → 原模型/工具循环 → repository.finish_turn。GET messages查看正文，GET tasks查看执行记录。

start_turn在短事务中验证归属、检查忙碌、读取历史、保存用户消息和started；return前提交并释放连接。run_ad_tool只接收普通list，保持模型调用期间没有该会话事务。finish_turn另开短事务，保存助手消息、终止事件、清除忙碌标记。模型失败时保存failed和安全错误码；未能保存失败的情况由后端日志记录task_id，禁止假报落盘成功。

## 三张表与新API

conversations：id/user_id/title/active_task_id/created_at。messages：会话编号/本轮任务编号/role/content及顺序编号。task_events：同一task_id的started与completed/limit_reached/failed，details存工具记录或安全错误码。任务事件采用追加记录，原课task_events单条业务通知的字段按本项目执行记录用途调整；用户归属由conversation外键关联检查。

UUID由uuid4生成，转换为字符串作为编号。Identity是PostgreSQL自动分配的整数编号；列表按id排序，允许编号有空档。DateTime(timezone=True)对应带时区时间，func.now由数据库填写；事务内多个时间戳可能相同，排序采用id。JSONB是PostgreSQL保存JSON结构的列类型，本块保存tool_results而非SQLAlchemy保留属性metadata。

Session.begin正常退出提交、异常退出回滚；with_for_update只在短事务中锁当前会话行。active_task_id在事务提交后仍保存“执行中”，其他请求读取后返回409。with_for_update锁随事务结束释放，active_task_id在finish_turn清空。原已学asyncio.to_thread继续让同步SQL在线程执行。

create_task保存后台启动任务对象；shield用于让外层取消时仍有机会取得已提交的task_id并清理。它覆盖活进程中的一次普通协程取消，进程强杀/数据库中断/重复取消等仍需要后续恢复策略。本块没有HTTP断开检测新增实现。

    )


class TaskEvent(Base):
    __tablename__ = "task_events"

        CheckConstraint(
            "status IN ('started', 'completed', 'limit_reached', 'failed')",
            name="task_events_status_check",
        ),
        UniqueConstraint("task_id", "status", name="task_events_task_status_key"),
        Index("task_events_conversation_id_id_idx", "conversation_id", "id"),

        Text, ForeignKey("conversations.id", ondelete="CASCADE"), nullable=False
    )
    task_id: Mapped[str] = mapped_column(Text, nullable=False)  # 同一轮的事件共用此编号。
    status: Mapped[str] = mapped_column(Text, nullable=False)  # 开始、完成、达到上限、失败。
    details: Mapped[dict] = mapped_column(JSONB, nullable=False)  # 工具记录或安全错误码。

### app/repositories/conversation_repository.py

```python
from uuid import uuid4  # 生成会话编号和任务编号。
from sqlalchemy import select
from sqlalchemy.orm import Session
from app.db.session import engine  # 复用全局连接池。
from app.db.models import Conversation, Message, TaskEvent


class ConversationNotFound(Exception):
    pass  # 交给HTTP层转换为404。


class ConversationBusy(Exception):
    pass  # 同一会话同时发送两条消息时，HTTP层返回409。


def owned(session, user_id, conversation_id, lock=False):
    query = select(Conversation).where(
        Conversation.id == conversation_id,
        Conversation.user_id == user_id,  # 在数据库查询中一起检查用户归属。
    )
    if lock:
        query = query.with_for_update()  # 本次短事务内，串行修改这条会话记录。
    conversation = session.scalar(query)
    if conversation is None:
        raise ConversationNotFound()
    return conversation


def create_conversation(user_id: str, title: str) -> dict:
    conversation_id = str(uuid4())  # 后端生成编号。
    with Session(engine) as session, session.begin():
        session.add(Conversation(id=conversation_id, user_id=user_id, title=title))
    return {"conversation_id": conversation_id, "title": title}


def list_conversations(user_id: str) -> list[dict]:
    with Session(engine) as session:
        rows = session.scalars(select(Conversation).where(
            Conversation.user_id == user_id
        ).order_by(Conversation.created_at.desc(), Conversation.id).limit(100))
        return [{"conversation_id": r.id, "title": r.title,
                 "active_task_id": r.active_task_id} for r in rows]


def read_conversation(user_id: str, conversation_id: str, events=False) -> list[dict]:
    with Session(engine) as session:
        owned(session, user_id, conversation_id)  # 查消息和任务时都先验证归属。
        table = TaskEvent if events else Message
        rows = list(session.scalars(select(table).where(
            table.conversation_id == conversation_id
        ).order_by(table.id.desc()).limit(100)))  # 界面最多返回最近100条。
        return [
            {"id": r.id, "task_id": r.task_id, "created_at": r.created_at.isoformat(),
             **({"status": r.status, "details": r.details} if events else
                {"role": r.role, "content": r.content})}
            for r in reversed(rows)  # 显示时按旧→新排列。
        ]


def start_turn(user_id: str, conversation_id: str, input_text: str) -> tuple[str, list]:
    task_id = str(uuid4())  # 一次请求对应一个任务编号。
    with Session(engine) as session, session.begin():
        conversation = owned(session, user_id, conversation_id, lock=True)
        if conversation.active_task_id:
            raise ConversationBusy()
        completed = select(TaskEvent.task_id).where(
            TaskEvent.conversation_id == conversation_id,
            TaskEvent.status == "completed",
        )  # 发给模型的历史只选已完成的对话轮次。
        rows = list(session.scalars(select(Message).where(
            Message.conversation_id == conversation_id,
            Message.task_id.in_(completed),
        ).order_by(Message.id.desc()).limit(20)))  # 最近20条已完成消息，通常对应10轮对话。
        history = [{"role": r.role, "content": r.content} for r in reversed(rows)]
        conversation.active_task_id = task_id  # 提交后，后续请求能看到“忙碌”。
        session.add(Message(conversation_id=conversation_id, task_id=task_id,
                            role="user", content=input_text))
        session.add(TaskEvent(conversation_id=conversation_id, task_id=task_id,
                              status="started", details={}))
    return task_id, history  # 离开with后已经提交并归还连接。


def finish_turn(user_id: str, conversation_id: str, task_id: str,
                result: dict | None, error_code: str = "execution_failed") -> None:
    with Session(engine) as session, session.begin():
        conversation = owned(session, user_id, conversation_id, lock=True)
        if conversation.active_task_id != task_id:
            raise ConversationBusy()  # 防止旧请求覆盖另一个任务。
        status = result["status"] if result else "failed"
        if result:
            session.add(Message(conversation_id=conversation_id, task_id=task_id,
                                role="assistant", content=result["answer"]))
        session.add(TaskEvent(
            conversation_id=conversation_id, task_id=task_id, status=status,
            details={"tool_results": result["tool_results"]} if result else
                    {"error_code": error_code},  # 保存安全错误码。
        ))
        conversation.active_task_id = None  # 回答与任务状态在同一事务提交。


def delete_conversation(user_id: str, conversation_id: str) -> dict:
    with Session(engine) as session, session.begin():
        conversation = owned(session, user_id, conversation_id, lock=True)
        if conversation.active_task_id:
            raise ConversationBusy()  # 执行中保留会话和记录。
        session.delete(conversation)  # 数据库外键负责级联删除消息和事件。
    return {"deleted": True}
```

### app/services/conversation_service.py

```python
import asyncio
import logging
from app.repositories.conversation_repository import start_turn, finish_turn
from app.services.llm_service import run_ad_tool  # 沿用已有模型与工具循环。

logger = logging.getLogger(__name__)


async def record_failure(user_id, conversation_id, task_id):
    try:
        await asyncio.shield(asyncio.to_thread(
            finish_turn, user_id, conversation_id, task_id, None
        ))  # 尽量让失败记录完成，并解除忙碌状态。
    except Exception:
        logger.exception("task failure persistence failed task_id=%s", task_id)


async def chat_in_conversation(user_id: str, conversation_id: str, input_text: str) -> dict:
    # 保存对启动线程的引用，以便请求取消后仍能取得任务编号并清理。
    starting = asyncio.create_task(asyncio.to_thread(
        start_turn, user_id, conversation_id, input_text
    ))
    try:
        task_id, history = await asyncio.shield(starting)
    except asyncio.CancelledError:
        try:
            task_id, _ = await starting  # 等短事务结束，取得已经提交的任务编号。
        except Exception:
            logger.exception("cancelled conversation start failed")
        else:
            await record_failure(user_id, conversation_id, task_id)
        raise  # 清理后保留请求取消的结果。

    try:
        result = await run_ad_tool(input_text, history=history)  # 模型拿到历史+本次输入。
        await asyncio.to_thread(finish_turn, user_id, conversation_id, task_id, result)
    except (Exception, asyncio.CancelledError):
        await record_failure(user_id, conversation_id, task_id)
        raise  # 原始错误交给HTTP层处理。
    return {"conversation_id": conversation_id, "task_id": task_id, **result}
```

import logging

def http_error(error: Exception) -> HTTPException:
    if isinstance(error, repository.ConversationNotFound):
        return HTTPException(404, "会话不存在或无权访问")
    if isinstance(error, repository.ConversationBusy):
        return HTTPException(409, "该会话有任务正在执行，请稍后发送")
    if isinstance(error, APITimeoutError):
        return HTTPException(504, "模型请求超时")
    if isinstance(error, (OpenAIError, OutputParserException)):
        return HTTPException(502, "模型调用或结果解析失败")
    if isinstance(error, (OperationalError, PoolTimeoutError)):
        return HTTPException(503, "业务数据库暂时不可用")
    logger.exception("conversation operation failed")  # 详细错误只进入后端日志。

def db_call(function, *args):
    try:
        return function(*args)  # 同步路由由FastAPI放在线程中运行。
    except (repository.ConversationNotFound, repository.ConversationBusy, SQLAlchemyError) as error:
        raise http_error(error) from error

## 失败与上线缺口

404：查不到本人可访问的会话。409：本会话忙碌，保护顺序。422：HTTP输入未通过Pydantic。502/504：模型调用/解析失败或超时。503：数据库连接/连接池不可用。其他错误500；客户端只收到安全提示，服务日志保留诊断信息。started与用户输入在同一事务，助手回答与完成事件在另一事务，模型等待分隔两笔事务。

本轮只提供失败事件的安全码，日志平台脱敏/访问控制留D25；task_id可用于定位该次执行。普通失败的failed落库也可能受数据库故障影响，日志记录后保留原异常。进程强杀可能留下active_task_id，D10/D23接任务恢复；当前候选适用于本地学习与所列正常失败验证。请求幂等键/重放待补，同一会话忙碌409只覆盖执行重叠场景。业务接口目前只查询，外部预算调整与通知尚未开放。

## 必背答案与综合题

Q：消息保存在数据库后，模型怎样知道以前说过什么？
A：后端按已验证用户与会话编号读取消息，转换为role/content列表，放到system之后、本轮user之前，再请求模型。保存记录与发送上下文是两步。

Q：为什么模型调用前后分两笔事务？
A：模型等待耗时较长。调用前短事务保存用户输入和开始事件，提交并释放连接；模型完成后用短事务保存回答和完成事件，降低连接池占用及持锁时间。

Q：user_id/conversation_id/task_id分别代表什么？
A：user_id确定调用者身份，conversation_id确定一段持续对话，task_id确定其中一次Agent执行。同一会话有多轮任务，每轮可有多条执行事件。

Q：刷新历史还在，能否说明模型记住历史？
A：刷新验证了数据库保存和历史接口；第二轮发送给模型的messages以及对原编号的正确引用，验证上下文接入。

Q：会话表active_task_id和行锁分别作用是什么？
A：短事务行锁让检查与更新忙碌标记按顺序发生；active_task_id把执行中状态保存在数据库，覆盖随后等待模型的时间。完成或失败时清空它。
