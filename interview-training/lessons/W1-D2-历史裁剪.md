## 为什么需要裁剪

完整历史可能有100条，本次只选择部分内容发给模型。完整存储用于查历史和追溯，本次模型输入用于回答当前问题。这两个数组分别检查。clear删除会话记录；trimMessages返回本次采用的消息。

本例4条历史为：

```text
1 user：企业管理员需要批量导入Excel，最多一万行。
2 assistant：已记录，行数适用范围待确认。
3 user：错误行需要导出。
4 assistant：已记录错误行导出，其他规则待确认。
```

最近2条为3和4，管理员/Excel的原话位于1。模型丢失这些事实有了可直接检查的原因：本次请求里已经缺少原话。独立保留当前已确认字段，可以在裁剪历史后继续提供这些事实。

## 新建文件，完整内容

路径：`C:\Users\Administrator\Desktop\newAgent\agent-course\interview-training\labs\w1-d2\trim-demo.ts`。

本例离线运行，使用固定问答验证消息选择；模型请求0次。为便于确定性观察，用消息条数计数，原生参数仍叫maxTokens。生产Token预算时传入所用模型的计数器或适合的估算器，并与供应商usage核对。

```ts
import {
  AIMessage,
  HumanMessage,
  SystemMessage,
  trimMessages,
} from '../../../chapter-02-工程底座/llm/services/chat/node_modules/@langchain/core/messages.js';

async function main() {
  const history = [
    new HumanMessage('企业管理员需要批量导入Excel，最多一万行。'),
    new AIMessage('已记录，行数适用范围待确认。'),
    new HumanMessage('错误行需要导出。'),
    new AIMessage('已记录错误行导出，其他规则待确认。'),
  ];

  const keepCount = Number(process.argv[2] ?? '2');
  if (!Number.isInteger(keepCount) || keepCount < 0) {
    throw new Error('保留条数需要填写0或正整数');
  }

  const trimmer = trimMessages({
    maxTokens: keepCount,
    tokenCounter: (messages) => messages.length,
    strategy: 'last',
    startOn: 'human',
    allowPartial: false,
  });

  const selected = await trimmer.invoke(history);
  console.log('原历史数量：', history.length);
  console.log('本次选中数量：', selected.length);
  console.log('本次选中内容：', selected.map((m) => m.text));

  const system = new SystemMessage([
    '根据用户消息和已确认数据整理需求。',
    '用户明确修改条件时采用最新条件。',
    '缺失信息标为待确认。',
  ].join('\n'));
  const current = new HumanMessage('改成最多五千行，其他要求保持不变。');

  const onlyRecent = [system, ...selected, current];
  console.log('只带最近历史的请求：', onlyRecent.map((m) => m.text));

  // 固定字段来自本例的user原话，演示独立保留已确认事实。
  const confirmed = {
    targetUser: '企业管理员',
    fileType: 'Excel',
    maxRows: 5000,
    limitScope: '待确认',
    exportErrorRows: true,
  };
  const facts = new HumanMessage(
    `按用户原话整理的当前需求数据：${JSON.stringify(confirmed)}`,
  );

  const withFacts = [system, facts, ...selected, current];
  console.log('补入已确认数据后的请求：', withFacts.map((m) => m.text));
  console.log('检查后原历史数量：', history.length);
}

main().catch((error: unknown) => {
  console.error(error instanceof Error ? error.message : '未知错误');
  process.exitCode = 1;
});
```

confirmed是教学固定样本，人工依据原user及本轮修改填写，maxRows已采用最新5000；本块验证事实保留与消息组装。实际系统需要抽取、校验、更新状态、来源与权限检查，沿用后续单元实现；摘要还要接受事实检查和预算控制。

## 参数逐项解释

| 参数 | 本例含义 |
|---|---|
| tokenCounter: messages.length | 每条消息计1个单位，所以这次预算按条数 |
| maxTokens: keepCount | 预算上限；传2时本例最多2条。改为真实Token计数器时，单位随之使用Token |
| strategy: last | 从最近的历史选择内容 |
| startOn: human | 保留段从用户消息开始；可能继续舍去前面的assistant |
| allowPartial: false | 保留完整消息，预算不足时整条舍去 |

4条历史且预算1时，最近一条是assistant，startOn:human会使保留结果为空。预算2时保留最后一组user/assistant；预算4时保留全部4条。includeSystem:true用于传入数组含首条system并希望保留它的情况；本例history只含问答，system单独加入并另外计预算。后续工具调用需保留调用消息与工具结果的对应关系。

课程按Token版本对应设置是tokenCounter:model、maxTokens:2000；具体模型的本地计数精度需要和供应商usage核对。当前练习采用条数让结果可预测，一条长消息仍可能很大，实际服务同时检查长度预算。

官方参数核对：[trimMessages](https://reference.langchain.com/javascript/langchain-core/messages/trimMessages)。

## 必背完整答案

1. Token是模型计量输入输出的单位；上下文窗口限制一次调用可处理的总量。预算需要给任务规则、本轮消息、历史、检索或工具内容以及生成回复留空间。
2. 历史裁剪选择本次发给模型的部分消息，完整存储仍可保留。strategy:last根据位置选择最近消息，关键事实可单独保存在经过核对的当前需求字段或摘要中，并计入请求预算。
3. 消息条数预算按条数计算，Token预算按所用计数器计算。需要同时检查计数方式、实际选中的消息和完整请求长度，按供应商实际usage复核效果。
