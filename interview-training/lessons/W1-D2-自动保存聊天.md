## 先认识代码里的几个名字

- `store`：Map，每个会话编号对应一组聊天记录。例如demo-a和demo-b分别保存自己的记录。
- `InMemoryChatMessageHistory`：在当前程序内存中保存消息，提供getMessages、addUserMessage、addAIMessage和clear。
- `getHistory(sessionId)`：按编号找记录；首次使用该编号时创建空记录。每次返回同一编号已有的记录，历史才能累积。
- `ChatPromptTemplate`：预先写好消息顺序；`{input}`处填本轮用户文字。
- `MessagesPlaceholder('history')`：在这里放入取出的历史消息。history为空时，这里放0条。
- `prompt.pipe(model)`：先填Prompt，再把填好的消息交给模型。示例在中间加一个打印函数，观察实际输入。
- `RunnableWithMessageHistory`：负责每次调用前读取历史、填入history，成功结束后保存本轮输入和回复。

`inputMessagesKey: 'input'`对上invoke的`{ input }`和模板`{input}`；`historyMessagesKey: 'history'`对上MessagesPlaceholder里的history。`sessionId`用来选择哪组聊天记录。本例编号是演示字符串，后续登录服务校验真实会话归属。

版本核对：本地@langchain/core为1.2.11，此API可执行；类型声明已标deprecated并推荐LangGraph持久化。本块完整学习原课程4.2.1，后续图课学习持久化替代方案。[官方API](https://reference.langchain.com/javascript/langchain-core/runnables/RunnableWithMessageHistory)。编辑器的弃用划线表达版本迁移建议。

```ts
import '../../../chapter-02-工程底座/llm/services/chat/src/load-env.js';
import { createChatModel } from '../../../chapter-02-工程底座/llm/services/chat/src/llm/model.factory.js';
import {
  ChatPromptTemplate,
  MessagesPlaceholder,
} from '../../../chapter-02-工程底座/llm/services/chat/node_modules/@langchain/core/prompts.js';
import {
  RunnableWithMessageHistory,
} from '../../../chapter-02-工程底座/llm/services/chat/node_modules/@langchain/core/runnables.js';
import {
  InMemoryChatMessageHistory,
} from '../../../chapter-02-工程底座/llm/services/chat/node_modules/@langchain/core/chat_history.js';

const store = new Map<string, InMemoryChatMessageHistory>();

function getHistory(sessionId: string) {
  let history = store.get(sessionId);
  if (!history) {
    history = new InMemoryChatMessageHistory();
    store.set(sessionId, history);
  }
  return history;
}

async function main() {
  const model = createChatModel();
  const prompt = ChatPromptTemplate.fromMessages([
    ['system', [
      '你是需求分析助手，根据用户消息整理需求。',
      '输出需求摘要、已知约束、待确认事项。',
      '用户明确修改条件时采用最新条件，保留其他已确认内容。',
      '缺失信息标为待确认，本轮最多问3个关键问题。',
    ].join('\n')],
    new MessagesPlaceholder('history'),
    ['human', '{input}'],
  ]);

  const chain = prompt
    .pipe((value) => {
      console.log('本次发给模型的消息：', value.toChatMessages());
      return value;
    })
    .pipe(model);

  const withHistory = new RunnableWithMessageHistory({
    runnable: chain,
    getMessageHistory: getHistory,
    inputMessagesKey: 'input',
    historyMessagesKey: 'history',
  });

  async function chat(sessionId: string, input: string) {
    const response = await withHistory.invoke(
      { input },
      { configurable: { sessionId } },
    );
    console.log('模型回复：', response.text);
  }

  await chat('demo-a', '企业管理员需要批量导入Excel，最多一万行。');
  console.log('第一轮后demo-a记录数：',
    (await getHistory('demo-a').getMessages()).length);

  await chat('demo-a',
    '改成最多五千行，错误行需要导出，其他要求保持不变。');
  console.log('第二轮后demo-a记录数：',
    (await getHistory('demo-a').getMessages()).length);

  console.log('demo-b记录数：',
    (await getHistory('demo-b').getMessages()).length);

  await getHistory('demo-a').clear();
  console.log('清空后demo-a记录数：',
    (await getHistory('demo-a').getMessages()).length);

  // 手动补入一组已知问答，演示append；这里的文字为固定样本。
  await getHistory('demo-a').addUserMessage('需要导入Excel。');
  await getHistory('demo-a').addAIMessage('已记录，导入规则待确认。');
  console.log('手动补入后demo-a记录数：',
    (await getHistory('demo-a').getMessages()).length);
}

main().catch((error: unknown) => {
  console.error('调用失败，错误类型：',
    error instanceof Error ? error.name : '未知错误');
  process.exitCode = 1;
});
```

## 对照代码理解过程

1. `store`放在main外；本次程序的两次chat共用这个Map。
2. 第一次chat的demo-a创建空历史；包装器读取0条，Prompt填本轮input，请求成功后写入2条。
3. 第二次chat沿用demo-a；包装器取旧2条插进history，本轮input继续放最后，成功后历史变4条。
4. `getMessages()`读取该会话全部已存消息。demo-b首次建立，数量0，证明本例按编号分别存储。
5. `clear()`清除demo-a；手动addUserMessage/addAIMessage演示补入已有问答，数量重新变2。包装器已保存的本轮问答只需保留一份，重复手动追加会使记录重复。
6. 日志中的HumanMessage表示user、AIMessage表示assistant，SystemMessage表示system；它们是库使用的消息对象。

进程结束后Map随内存释放。再次运行脚本从空历史重新开始。生产环境在D07把会话消息持久化到数据库；会话归属校验、历史读取、模型输入组装和结果保存分别验证。

## 必背完整答案

1. 自动会话历史处理分四步：按会话编号读取旧消息，把旧消息与本轮输入组成模型请求，调用模型，成功后保存本轮用户消息和模型回复。模型依据本次收到的消息作答。
2. 会话编号用于找到对应聊天记录；同一会话沿用同一编号，不同会话分别存储。接口还要校验该会话属于当前登录用户，之后才允许读取和更新。
3. 内存历史保存在当前进程中，进程结束后释放。数据库持久化支持重启后继续读取；消息裁剪控制本次发给模型的内容，数据库和完整历史的删除由另外的业务操作处理。
