## 关键错误的定位

| 现象 | 对应检查 |
|---|---|
| 供应商429或超时 | request阶段，后续解析和校验尚未执行 |
| 文本JSON语法残缺 | parse阶段 |
| JSON语法成立，字段类型错误或问题超数量 | validate阶段 |
| 类型和数量通过，仍编造事实或重复询问 | 对照当前已确认条件、用户原话和问题含义 |
| 第二轮回答未知 | 检查实际发送内容、thread_id、状态读取、对象复用与裁剪 |
| 服务重启后内存状态消失 | 检查存储实现；数据库checkpointer用于持久化恢复 |

手动解析路径：模型文本 → JSON.parse → Schema。withStructuredOutput将结构化解析与校验封装在调用中，外层继续处理异常和业务事实。
