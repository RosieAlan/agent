# 工具调用第一讲：从普通函数到模型选择

2026-10-16。依据TEACHING-MAP.md，原3.8.1–3.8.3，岗位Tool Calling。阅读课：代码为分步教学片段，网页实作与完整执行过程在下一讲合并；本课新增理解待学生口述验收。

## 问题与目标

用户问“订单A1024发货了吗？”后端查询功能提供订单状态。模型需要知道可选工具的名称、用途、参数规则，才能提出调用请求。必会解释tool、bindTools、模型invoke、tool_calls各自输入输出和执行时机。

## 1. 普通函数

```ts
async function queryOrder({ orderId }: { orderId: string }) {
  if (orderId === "A1024") {
    return { found: true, orderId, status: "已发货" };
  }
  return { found: false, orderId };
}
```

这是模拟查询：A1024的状态写在代码里。真实查询将在接入数据库时替换，并加入身份与订单归属校验。函数接收包含orderId的对象；解构取得订单号；异步返回查询结果。调用await queryOrder({ orderId: "A1024" })才执行函数。

## 2. 创建工具对象

tool来自@langchain/core/tools，沿用原课程和项目导入；z来自zod，沿用已学的参数校验。tool的第一个参数是函数本身，第二个参数是配置，返回LangChain工具对象。

```ts
import { tool } from "@langchain/core/tools";
import { z } from "zod";

const queryOrderTool = tool(queryOrder, {
  name: "query_order",
  description: "根据订单号查询订单是否存在及发货状态；适用于用户询问订单进度。",
  schema: z.object({
    orderId: z.string().min(1).describe("用户提供的订单号，例如A1024"),
  }),
});
```

name是模型返回调用请求时使用的标识；description帮助模型理解用途；schema说明参数结构并用于执行时校验。min(1)限制至少一个字符；describe添加字段说明。TypeScript的string检查开发期类型；Zod检查运行时数据。字符串格式正确和订单存在分别由参数校验和业务查询确认。

queryOrder是函数变量，query_order是工具标识，queryOrderTool是包装后的对象。tool(queryOrder,配置)记录函数；queryOrder(参数)执行函数。

## 3. 配置给模型并发请求

以下承接已有的model聊天模型对象和上面定义的queryOrderTool，作为教学片段：

```ts
const modelWithTools = model.bindTools([queryOrderTool]);
const reply = await modelWithTools.invoke([
  { role: "user", content: "订单A1024发货了吗？" },
]);
```

bindTools接收工具数组，返回配置好工具定义的模型调用对象。随后invoke发送用户消息及工具定义，获取模型回复。对于本课本地自定义工具，函数代码留在后端，模型获取用于选择工具和填写参数的定义。绑定工具与发送模型请求都尚未执行queryOrder。

模型可能返回如下调用请求，具体id由实际响应决定：

```json
{
  "name": "query_order",
  "args": { "orderId": "A1024" },
  "id": "call_example"
}
```

该对象位于reply.tool_calls数组；name指要用哪个工具，args是执行参数，id用于关联后续工具结果。此时订单状态仍等待后端执行查询获取。模型也可能直接回答或索要缺失的订单号，调用结果按实际响应分支处理。

## 必背与检查题答案

必背：tool把业务函数及名称、用途、参数规则组织成工具对象；bindTools给模型调用配置工具定义；模型invoke发请求获取回复，tool_calls记录模型提出的工具名称和参数；后端随后执行工具并回传结果。

1. 写完tool(queryOrder,配置)，订单查询运行了吗？答案：此时完成工具定义；查询在后端调用工具执行方法时运行。
2. 模型返回args中orderId是数字123，应该在哪处理？答案：后端执行前按Schema校验，字符串字段收到数字应报参数错误，数据库查询保持未执行。还需检查实际工具入口确实使用校验。
3. description写“万能助手”有什么问题？答案：用途含糊，模型难以区分查询订单和其他功能；应明确输入订单号、返回订单状态及适用场景。
