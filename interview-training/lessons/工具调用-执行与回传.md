# 工具调用第二讲：执行工具与回传结果

2026-10-16，对应原3.8.4–3.8.5及4.3。本课沿用上一讲模拟订单queryOrderTool与已创建的model。阅读课片段，网页接入与学生真实运行待验收。

## 完整过程

用户提问→第一次模型调用→AIMessage包含tool_calls→后端执行工具→ToolMessage保存结果→第二次模型调用→最终回答。一次查询常见两次模型调用及一次工具执行；模型也可直接回答或请求多个工具，次数依据实际分支。

## 代码与新概念

ToolMessage从@langchain/core/messages导入，是记录工具结果的消息类型；content保存结果文本，tool_call_id对应先前工具调用的id。messages必须保留模型原始调用请求，再追加每个工具结果。模型不会自动读取后端变量result，需要把结果作为消息再次发送。

以下为承接上一讲的片段：model已初始化；queryOrderTool已按上一讲定义。工具对象的invoke执行本地函数并按其Schema校验参数；聊天模型的invoke发送模型请求，方法名相同、接收对象不同。

```ts
import { HumanMessage, ToolMessage, type BaseMessage } from "@langchain/core/messages";

const modelWithTools = model.bindTools([queryOrderTool]);
const messages: BaseMessage[] = [
  new HumanMessage("订单A1024发货了吗？"),
];
const firstReply = await modelWithTools.invoke(messages);
messages.push(firstReply);

const calls = firstReply.tool_calls ?? [];
if (calls.length === 0) {
  console.log(firstReply.content);
} else {
  for (const call of calls) {
    if (call.name !== queryOrderTool.name) {
      throw new Error(`未知工具：${call.name}`);
    }
    if (!call.id) {
      throw new Error("工具调用缺少id");
    }
    const result = await queryOrderTool.invoke(call.args);
    messages.push(new ToolMessage({
      tool_call_id: call.id,
      content: JSON.stringify(result),
    }));
  }
  const finalReply = await model.invoke(messages);
  console.log(finalReply.content);
}
```

BaseMessage是这些消息类型的共同TypeScript类型；messages允许放用户消息、AI消息及工具结果。new HumanMessage创建用户消息；firstReply是模型返回的AI消息。?? []在tool_calls缺失时使用空数组。for遍历本次全部工具请求，依次回传结果。throw让此教学调用报错退出；接口级错误展示在可靠性主题完成。

最后使用model.invoke，发送已收集的查询结果并生成本轮回答，此步骤使用普通模型调用。多步Agent则继续使用绑定工具的模型，检查是否又返回tool_calls，并设置退出条件及轮次上限。生产查询还需后端身份与订单归属校验；本例只访问上一讲代码里的模拟数据。

## 查看消息顺序

第一次：HumanMessage(订单问题)。第二次：HumanMessage(订单问题)＋AIMessage(请求query_order，id为call_example)＋ToolMessage(查询结果，tool_call_id为call_example)。工具结果如found=true,status=已发货，模型据此回复。found=false时应如实表示未查到，保留事实来源。

## 必背标准答案

模型返回tool_calls后，后端识别工具、校验参数并执行函数，保留模型原始调用消息，再把每次结果包装成ToolMessage，用tool_call_id关联调用编号；随后将完整消息发给模型生成回答。

面试追问一：工具结果已存在result变量，为什么还要发请求？答案：result只存在于后端程序，模型通过第二次请求中的工具消息获取查询结果。

面试追问二：查询结果的id为什么要对应？答案：模型可能一次请求多个工具，编号明确每条结果属于哪一次调用，确保消息协议和结果对应正确。

练习：口述第二次请求中三种消息各包含什么；排查“工具查到已发货，模型仍说无法查询”时，检查result是否追加成ToolMessage、编号是否匹配、再次invoke是否发送更新后的messages。学生口述与真实实操分别记录。
