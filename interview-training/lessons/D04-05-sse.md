## 从已经会的invoke开始

invoke等待完整AIMessage，拿到response.text后一次返回。stream返回异步可迭代的消息块，for await每收到一块便执行一次循环。块中可能包含一段文字、空文字或元数据；文字块大小由上游实现决定。

场景：解释“员工报销超过2000元由主管审批”可能陆续收到“核心功能”“：报销审批”“。明确约束……”。前端追加这些文字，就形成连续显示效果。模型生成速度与网络传输分别影响体验，流式主要缩短首次可见内容的等待。

完整过程：浏览器POST原文 → Controller校验 → Service调用model.stream → Controller把消息块包装成SSE → 浏览器读取响应体并追加文字 → 收到done标记成功。用户取消继续沿用AbortController，服务端close将取消信号传给模型。

## 先理解两种数据格式

SSE（Server-Sent Events）是服务器通过HTTP响应持续发送事件的格式。本例每个事件采用data行加空行：

```text
data: {"type":"delta","text":"核心功能"}

data: {"type":"delta","text":"：报销审批"}

data: {"type":"done"}

```

实际代码用`data: ${JSON.stringify(event)}\n\n`。JSON.stringify负责转义正文换行、引号；末尾两个换行表示事件结束。Content-Type声明text/event-stream，正文同时遵守事件格式。原课程最小示例直接write文字，工程练习补齐事件边界和成功/失败协议。

type是本项目自定字段：start开始、delta新增文字、done完整成功、error失败。HTTP响应头发出后状态码已经确定，后续生成失败通过error事件告诉页面；输入校验在响应头发出前执行，非法输入仍返回HTTP400。HTTP200后还要检查业务done。

模型输出JSON与SSE事件JSON分别处理。本课delta传递展示文字；结构化结果继续使用原structured接口做Schema校验。原6.5.4要求Markdown文字逐段推送，UI组件完整校验后再发送，进度单独发送，done后按业务规则保存最终结果。中途断连的部分结果需明确标记未完成。

## 新API及执行时机

| 写法 | 来源、参数与结果 |
|---|---|
| model.stream(messages, {signal}) | LangChain模型方法，输入消息数组与取消配置；await后得到异步可迭代流 |
| model.withConfig({maxRetries: 0}) | 本地模型支持的调用配置，本次流请求关闭自动重试；已有文字后整体重放需另设计去重与恢复 |
| for await (const chunk of stream) | JS异步遍历，等待下一块；chunk.text读取当前可见文字 |
| res.write(string) / res.end() | Express使用的Node响应对象，分别写一段和结束响应；本例@Res()由Controller完整管理响应 |
| res.flushHeaders() | Node响应方法，立即发送响应头，页面可开始读流 |
| response.body.getReader() | 浏览器Fetch响应体方法，返回reader；reader.read()等待下一批字节，得到{value, done} |
| new TextDecoder().decode(bytes, {stream:true}) | 浏览器内置UTF-8解码器，保留跨批次的未完整字符字节，避免中文被拆坏 |

reader.read的done表示HTTP响应体读完；我们自定义的type:done表示业务成功。网络读取的一批字节可能包含半个事件，也可能包含多个事件，因此前端保留buffer，凑齐空行再JSON.parse。

reader.cancel()用于停止继续读取，reader.releaseLock()释放当前读取器对流的占用；放在finally处理正常与异常路径。React的setOutput(current => current + text)基于最新页面状态追加本段文字，沿用已有useState。

## 学生修改二：Controller原stream方法

文件：services/chat/src/llm/llm.controller.ts（相对上面的llm项目根目录）。仅替换@Post('stream')对应方法；原structured及其他方法保留。Body、Post、Res、BadRequestException、RequirementSchema、Response已经导入。

```ts
@Post('stream')
async stream(@Body() body: unknown, @Res() res: Response) {
  const checked = RequirementSchema.safeParse(body);
  if (!checked.success) {
    throw new BadRequestException('input必须是非空字符串');
  }

  const client = new AbortController();
  const timeout = AbortSignal.timeout(30_000);
  const signal = AbortSignal.any([client.signal, timeout]);
  const onClose = () => {
    if (!res.writableEnded) client.abort();
  };
  const send = (event: object) => {
    if (!res.destroyed && !res.writableEnded) {
      res.write(`data: ${JSON.stringify(event)}\n\n`);
    }
  };
  res.on('close', onClose);

  try {
    res.status(200);
    res.setHeader('Content-Type', 'text/event-stream; charset=utf-8');
    res.setHeader('Cache-Control', 'no-cache');
    res.setHeader('X-Accel-Buffering', 'no');
    res.flushHeaders();
    send({ type: 'start' });

    const stream = await this.llmService.streamDemo(checked.data.input, signal);
    for await (const chunk of stream) {
      signal.throwIfAborted();
      if (chunk.text) send({ type: 'delta', text: chunk.text });
    }
    signal.throwIfAborted();
    send({ type: 'done' });
  } catch {
    if (!client.signal.aborted) {
      const timedOut = timeout.aborted && signal.reason === timeout.reason;
      send({
        type: 'error',
        message: timedOut ? '生成超时，请重新提交' : '生成失败，请重新提交',
      });
    }
  } finally {
    res.off('close', onClose);
    if (!res.destroyed && !res.writableEnded) res.end();
  }
}
```

按顺序读：校验 → 准备取消/超时 → 注册断连监听 → 发送响应头/start → 循环发送delta → 正常done/异常error → 清监听并结束。X-Accel-Buffering用于提示Nginx关闭缓冲；生产代理还要核对自身配置。断连后客户端已离线，服务端继续传递取消并清理。本次配置30秒取消信号，上游及库响应取消的耗时需实测。

本流式入口沿用原LlmService，当前结构化入口的RequirementService限流只覆盖structured。两个路由共享准入控制、慢客户端写入背压、代理超时/心跳、鉴权与多实例限流列为后续综合/生产扩展，部署前逐项处理；本课在本地单次请求验证事件与取消。

## 学生修改三：现有/d03页增加流式按钮

第一步：在import之后、export default function D03Page之前加入这个函数。它是本项目的受控事件格式读取器，支持本课data单行、LF/CRLF、跨包UTF-8；完整SSE通用解析器还需覆盖id/retry等语义。

```ts
async function readSse(response: Response, onText: (text: string) => void) {
  if (!response.body) throw new Error('响应缺少流式内容');
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = '';
  try {
    while (true) {
      const { value, done } = await reader.read();
      buffer += done ? decoder.decode() : decoder.decode(value, { stream: true });
      buffer = buffer.replace(/\r\n/g, '\n');
      let boundary: number;
      while ((boundary = buffer.indexOf('\n\n')) >= 0) {
        const frame = buffer.slice(0, boundary);
        buffer = buffer.slice(boundary + 2);
        const data = frame.split('\n')
          .filter(line => line.startsWith('data:'))
          .map(line => line.slice(5).replace(/^ /, '')).join('\n');
        if (!data) continue;
        const event = JSON.parse(data);
        if (event === null || typeof event !== 'object') {
          throw new Error('事件格式错误');
        }
        if (event.type === 'delta') {
          if (typeof event.text !== 'string') throw new Error('文字事件格式错误');
          onText(event.text);
        } else if (event.type === 'error') {
          throw new Error(typeof event.message === 'string' ? event.message : '生成失败');
        } else if (event.type === 'done') {
          return;
        } else if (event.type !== 'start') {
          throw new Error('收到未知事件');
        }
      }
      if (done) throw new Error('连接已结束，结果尚未确认完成');
    }
  } finally {
    await reader.cancel().catch(() => {});
    reader.releaseLock();
  }
}
```

第二步：在D03Page函数内、现有return JSX之前加入sendStream。requestRef防重复请求，finally恢复按钮；取消和失败保留已经显示的文字。

```ts
async function sendStream() {
  if (requestRef.current) return;
  const controller = new AbortController();
  requestRef.current = controller;
  setLoading(true);
  setOutput('');
  try {
    const response = await fetch(
      `${process.env.NEXT_PUBLIC_API_BASE_URL}/api/langchain/stream`,
      {
        method: 'POST',
        headers: { 'Content-Type': 'application/json', Accept: 'text/event-stream' },
        body: JSON.stringify({ input }),
        signal: controller.signal,
      },
    );
    if (!response.ok) throw new Error(`HTTP ${response.status}：${await response.text()}`);
    if (!response.headers.get('content-type')?.includes('text/event-stream')) {
      throw new Error('接口返回的内容类型与流式协议不符');
    }
    await readSse(response, text => setOutput(current => current + text));
    setOutput(current => current + '\n\n【生成完成】');
  } catch (error) {
    const message = controller.signal.aborted
      ? '已取消本次请求，以上内容尚未完成'
      : error instanceof Error ? error.message : '生成失败';
    setOutput(current => current + `\n\n【${message}】`);
  } finally {
    requestRef.current = null;
    setLoading(false);
  }
}
```

## 必背与面试答案

1. SSE是什么？服务器通过HTTP响应持续发送事件。后端用text/event-stream响应类型，按data行和空行发送事件；前端读取并逐段更新页面。连接结束、生成完成、生成失败分别判断，成功依赖应用协议的done。
2. 流式为什么需要buffer？一次网络读取与一个业务事件大小各自独立。前端累计字节解码后的字符串，遇到完整事件边界才解析，保留下一次要用的剩余文字；TextDecoder的stream选项保留未完整字符的字节。
3. 页面已有文字后失败怎么办？保留部分内容，标记失败/未完成，清理等待状态与监听，取消上游调用。重新执行可能重复生成或发生工具副作用；需要业务去重、检查点和恢复协议后再支持透明重连重跑。

综合检查及标准答案：HTTP200后error事件仍判失败；读到done:true但没收到type:done判未确认完成；文字增量用于展示，结构化业务对象收齐并校验后使用。独立题：把前端error分支删除会怎样？当前读取器将其识别为未知事件并失败，页面失去后端具体可公开错误说明；把EOF一律当成功会误报被截断结果。
