# 电商智能投放与多Agent创作平台：第二项目规格

状态：2026-11-10正式开始第二项目。当前目录仅有占位文件与说明，业务代码从独立目录逐步实现。

## 用户与首条任务

目标用户为电商运营和投放负责人。首条任务：查看指定店铺、日期范围内的广告活动，识别需要关注的活动，展示指标与证据，生成优化方案草案；预算变化经人工批准后执行允许的操作。业务数据先使用标记synthetic_demo的固定样例，真实模型继续qwen3.8-flash，第三方广告接口在取得可用授权后接入。

## 两条完整业务主线

1. 投放：接收目标→澄清店铺/日期/指标口径→查广告报表→确定性计算指标→检索规则→多专家诊断→方案草案→预算调整预览→审批→版本与幂等检查→受控执行→结果核验与复盘。
2. 创作：会话选择成员及@角色/Skill/文件/商品主体→联合解析与素材校验→澄清确认→规划生成→图像/视频任务提交与状态恢复→产物版本/对象存储→评审与多轮修改→交付。

## 第一块可验收功能

建立独立Python/FastAPI后端，接收店铺、日期和广告数据，校验口径并输出结构化指标。使用固定样例验证零花费/零点击/零曝光、按合计数重新计算比率、币种与日期一致性。明确区分广告归因销售额与利润，不以ROAS单独推断盈利。第一步先完成可靠数据和接口，再接入模型诊断；指标公式作为已给业务规则使用，重点讲数据链路、校验和边界。

## 完整范围继续保留

Python/FastAPI/Pydantic、MySQL/SQLAlchemy/Alembic；LangChain/Function Calling/LangGraph、Supervisor/规划执行/重规划/长任务/checkpointer/HITL；RAG/混合召回/Rerank/引用、MCP/Skills/DeepAgent专项；Mem0长期偏好与精确业务状态隔离；Redis缓存/任务/并发；Vue/TypeScript、SSE、AI SDK UI消息流兼容、AG-UI；商品主体/附件/素材多模态、图像视频API、OSS/FileMS；Langfuse/评估/成本、权限/沙箱/审计，以及Docker/Linux/Nginx/HTTPS/CI/CD/备份/恢复/高可用部署。

各组件在实际功能需要时接入；原27份课程及截图要求映射继续由interview-training中的计划和覆盖表维护。第一项目延期主题转对应第二项目阶段补学，教学验证和学生独立掌握分别记录。

## 质量门槛

当前示例门槛：预算执行必须匹配已批准方案版本、用户/店铺授权和执行幂等键；未经批准的写入及无依据的成功状态属于关键失败。数值与字段采用程序检查，自由文本采用标注样本、明确规约和人工校准。具体题数、通过率、延迟和成本门槛在建立基线后确定，模拟阈值不得作为已测生产收益。CI中模型评测使用独立测试数据与专门凭据，按手动/定时/发布触发控制费用。

## 实施顺序

1. 广告数据输入、校验、指标与查询接口。
2. 单活动诊断及依据，扩展多活动任务计划与专家协作。
3. 方案、审批、执行、幂等并发、长任务恢复。
4. 会话成员/@选择、Skill、主体与素材、多模态生成和多轮交付。
5. 记忆、事件协议、评测与成本、治理和双项目统一部署验收。

每阶段交付完整可运行功能；新增文件职责、调用链、关键代码和运行命令在对话中讲解。
