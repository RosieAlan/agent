# 第七章面试题与参考答案

题目按 7.1～7.7 的学习进度补充，重点是场景判断与方案取舍。

## 7.1 固定编排与三层决策

### 问题 1：五段式需求分析里每个 Agent 都会判断，为什么还叫固定编排？

参考答案：模型判断发生在节点内部，例如提取字段或评估风险；可走的分支仍由代码预先列出。本地已有“需要澄清就提前返回”的条件分支，以及分析、风控并行步骤。固定编排描述开发期列出的路径范围，局部推理描述节点内部的判断；当任务类型和中间结果要求选择不同链路或插入新步骤时，需要更明确的运行时路径决策。

### 问题 2：收到“请评审 50 条需求，先查冲突，再估工期，最后汇总”的任务，你会先在哪一层做决策？

参考答案：先确认任务已进入批量评审链路；执行层采用 Plan-and-Execute 列出查询、冲突检查、过滤、估算与汇总的依赖。最终报告可在优化层使用 Critic-Refine 检查遗漏。单一批量评审入口可以直接进入执行层。

### 问题 3：需求报告缺少一段依赖说明，需要改变 Router 吗？

参考答案：优先在优化层对报告做局部 Critic-Refine，补齐依赖说明。Router 的职责是选择目标链路，报告内容修订属于产出质量问题。若发现整条链缺少依赖分析步骤，再评估执行层流程设计。

## 7.2 路由层

### 问题 1：系统有功能、性能、安全三条分析链，Router 应返回什么？

参考答案：返回受系统约束的目标链标识，例如 `functional`、`performance`、`security`，并记录分类依据或置信信息。下游依据标识进入对应 Workflow。Router 负责选链；各 Workflow 负责本领域的分析步骤。

### 问题 2：用户说“批量导入 Excel，只允许管理员使用，还要三秒内完成”，强制单选一条链会有什么问题？

参考答案：输入同时包含功能、安全和性能约束。强制单选可能遗漏关键维度；可拆成多个子任务，分别进入专门链后汇总，也可先澄清优先目标。生产路由还应定义低置信度和混合标签的处理方式。

### 问题 3：当前页面已有功能/性能/安全选择卡片，是否已经实现课程中的 Router？

参考答案：页面目前让用户手动选择类型，后续进入相同的表单流程；这些选择尚未接到不同的分析 Workflow。课程中的 Router 需要将分类结果用于实际分派，目标链路应有清晰不同的处理步骤。

## 7.3 执行层

### 问题 1：用户的需求描述模糊，查相似需求后的结果会决定下一步查冲突还是先澄清，应选哪种执行策略？

参考答案：选择受控 ReAct 循环。每次读取工具结果后再决定下一步，适合强依赖中间观察的探索任务。设置允许的工具、最大轮次与停止条件，记录动作和结果供排查。

### 问题 2：批量评审 50 条需求，先查冲突，再对合格项估算工期，部分查询失败时如何继续？

参考答案：使用 Plan-and-Execute 先明确步骤依赖和可并行部分。保存已完成需求及结果、失败项和剩余任务；查询失败或计划前提改变时基于这些状态 Replan，避免重复处理已完成项。

### 问题 3：Plan-and-Execute 的 Executor 能否调用 ReAct 或 Fixed Workflow？

参考答案：可以。Planner 定义整体目标和依赖；Executor 的某一步可调用标准 Workflow 处理清晰需求，也可用有边界的 ReAct 探索模糊需求。组合时明确每步输入、输出、失败处理和终止条件。

## 7.4 优化层

### 问题 1：最终报告遗漏“最多一万行”，调查发现 extractAgent 从原始需求中漏提了该约束，应怎样修？

参考答案：上游理解错误已经影响分析和风险结论，应从受影响的上游步骤重新执行。Reflexion 可让 Evaluator 指出漏提条件，由 Reflector 提炼修正意见，再由 Actor 带着意见重跑，并限制重试轮次。

### 问题 2：各 Agent 的中间结果完整，最终报告仅漏写外部系统依赖，应怎样控制修订成本？

参考答案：使用 Critic-Refine。Critic 明确指出缺失的段落和已有依据，Refiner 局部修改报告，保留其余可信结果。修订后检查引用和前后文一致性。

### 问题 3：风险等级在 P1 与 P2 之间摇摆，多次投票能否直接保证正确？

参考答案：Self-Consistency 可以让多个尽量独立的判断提供稳定性线索，投票结果仍需对照明确的业务证据与评级标准。高影响评级应保留分歧并支持人工复核，避免将多数意见当作事实证明。

## 7.5 模式组合

### 问题 1：系统已有功能、安全两条分析链，收到“批量导入 Excel，只有管理员能上传”，如何组合三层？

参考答案：路由层识别功能与安全两个维度，执行层调用对应分析步骤并合并证据；优化层检查报告是否覆盖权限约束，必要时局部修订。最终结果可组织成 UI 协议返回页面。混合需求需定义多标签或拆分规则。

### 问题 2：只有一条稳定的标准需求分析链，还需要 Router 和 Critic 吗？

参考答案：可以直接进入 Fixed Workflow。若有明确质量规则或经验证的缺漏问题，再按需要加入结果校验或 Critic；每层都应有可观察的收益与成本预算。

### 问题 3：批量评审计划中的一条需求很模糊，如何在 Plan-and-Execute 中处理？

参考答案：Planner 保持批量任务的全局依赖；Executor 可把该模糊条目交给有工具和轮次限制的 ReAct 子步骤，清晰条目继续使用固定流程。子步骤返回结构化结果后纳入共享计划状态；失败或前提变化时只对剩余任务 Replan。
